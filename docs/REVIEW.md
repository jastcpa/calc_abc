# Код- и секьюрити-ревью

Проверено вручную по всему коду `tgbot/` + регрессионные тесты (`php tests/run.php`).

## Ролевая модель (RBAC) — ревью
- Права проверяются на сервере на каждом запросе (страница + каждое изменяющее действие), пользователь и его права перечитываются из БД при каждом запросе: деактивация, смена роли/ботов, сброс пароля действуют немедленно (`sess_ver` завершает чужие сессии).
- Ограничение по ботам применяется в SQL (`scope_sql`) ко всем спискам, счётчикам, дашборду, экспорту и массовым действиям; прямые ссылки на чужие записи ведут на редирект; ID из форм фильтруются по доступным.
- Повышение привилегий закрыто: управление командой/ролями/ботами/настройками только у админа (403 даже прямым POST); профиль не меняет роль; роль администратора неизменяема; «последний админ» защищён; неизвестные права из БД игнорируются.
- Найдено при ревью и исправлено: счётчики по группам и клики в воронках на дашборде/в рассылке считались по всем ботам (утечка агрегатов ограниченному пользователю) — теперь учитывают доступ.
- Остаточное: названия групп общие для всех ботов и видны всем с правом `groups.view`.

## Проверено, замечаний нет
- SQL: везде prepared statements; интерполируются только `int`-значения (ID групп/ботов приводятся к int).
- XSS: весь вывод через `h()`; превью сообщений — серверный HTML после `htmlspecialchars`, ссылки только `http(s)/tg`, кавычки в URL исключены.
- CSRF: все изменяющие запросы — POST с токеном; сессия `HttpOnly`, `SameSite=Lax`, `Secure` при https; `session_regenerate_id` при входе.
- Пароль — `password_hash`; секреты — `random_bytes`; токен бота маскируется в ошибках cURL.
- Доступ к файлам: `.htaccess` закрывает `data/`, `lib/`, `tests/`, `config.php`, `*.sqlite`, `*.log`, `*.md`.

## Остаточные риски / рекомендации
- Первый, кто откроет `install.php` до владельца, станет админом → удалите файл сразу после установки.
- На Nginx `.htaccess` не работает — добавьте `deny` для `data/`, `lib/`, `tests/` (см. INSTALL.md).
- Ключ постбека в query-строке попадает в логи веб-сервера: для серверных вызовов используйте заголовок `X-Postback-Key`, при утечке — «Сменить ключ».
- Подписанную ссылку трекера можно использовать повторно для накрутки кликов этого пользователя (редирект только на ссылку самой кнопки — open redirect исключён).
- SQLite хватает для десятков тысяч пользователей; для сотен тысяч и частых рассылок стоит перейти на MySQL/PostgreSQL.
- Если обработка апдейта упала после записи `update_id`, Telegram его не повторит (ошибки пишутся в `data/error.log`).
